# AWS Bedrock Reference — デザイン案 01

`bedrock-explorer.html` をブラウザで開いて確認できます。既存の `src/` と本番ビルドには影響しない、単一HTMLのモックアップです。外部フォント・画像・ライブラリは使っていません。

## デザインの狙い

- GPU側の `AWS GPU Reference` に合わせて、サイト名を `AWS Bedrock Reference` とする。キャッチコピーは置かず、ヘッダ直下から比較操作に入れる。

- 明るい背景と深緑を基調に、起点リージョン、検索条件、比較表の優先順位を明確にする。
- In-Region / Geo / Global に日本語の見出しを添え、意味を比較しやすくする。
- モデル名を選ぶと右側に推論先と呼び出し用IDを表示する。モバイルでは表の下に配置する。
- 推論先を国内に限定した場合は、その条件に合う使い方だけを表示する。

## 試せる操作

リージョン選択（5地域）、モデル名・ID検索、提供元フィルタ、日本国内限定、モデル選択、推論方法切り替え、IDコピー。コピーはブラウザの権限により利用できない場合があり、その場合は手動コピーを案内します。

## 範囲

設計書 `docs/apd/design.md` をもとにした画面構成案です。モデル・推論先・標準価格は、作成時点の `data/` のスナップショットから7モデルを抜粋してHTMLに埋め込んでいます。最新情報の照会は行っていません。データ更新は自動反映されません。

全リージョン行列、任意の推論先限定、Mantle、詳細な監査ログの説明、言語・テーマ切り替え、URL共有は未実装です。本番へ採用する際は既存機能との統合が必要です。

## デザイン案 02：現行の情報量を保つ改善案

`bedrock-reference-v2.html` が改訂案です。こちらもブラウザで直接開ける単一HTMLです。

- 現行のビルド済みアプリを使い、全モデル・全列・行内詳細・リージョン行列を維持。
- GPU Reference に合わせたコンパクトな見出し、グレーとアンバーの配色。ライト／ダーク両方に対応。
- 提供元・モダリティの複数選択をチェックボックス付きメニューに変更。検索と推論先の限定を同じ行に配置。
- 接続情報は開閉式。Globalの共通注記を表の上に集約し、各行には可否とGlobal価格を残す。
- 推論方法の3列を同系色の見出しでまとめ、標準価格と区切る。
- 行内詳細は推論先の図とID・推論先・価格を横に並べる。スマートフォンでは縦に配置し、表と図はそれぞれ横スクロール。
- 国内Geoでも「国外に出ることはある」と表示される現行の日本語キャプションは、このモックアップ内のみ「定義された推論先のいずれかで実行」という表現に変更。判定・推論先データは変更していない。

### 再生成

```sh
npm run build
node docs/mockups/build-reference-v2.mjs
```

編集対象は `reference-v2.css` と `reference-v2.js`。ビルド結果にモックアップ専用のスタイル・表示処理を追加する構成で、`src/` と生成データは変更しません。生成したHTMLは作成時のスナップショットで、自動更新されません。本番採用時には既存コンポーネントへの統合が必要です。

### 確認

既存テスト690件成功。ブラウザで検索、提供元の複数選択、リセット、推論先限定、起点切り替え、未取得表示、詳細の推論方法切り替え、リージョン行列、日英切り替え、ライト／ダークを確認。375px幅ではページ全体の横はみ出しがなく、表の固定列が横スクロール中も重ならないことを確認。

## デザイン案 03：リージョンの概要と比較を分ける案

`bedrock-reference-v3.html` は、白・青の配色と画面構成を変更した別案です。

- 起点リージョンの見出しと、In-Region / Geo / Globalの利用可能モデル件数を上部に配置。
- 件数は絞り込み後の表から集計。推論先の条件に合わない使い方を除外し、未取得のリージョンは「—」にする。方式間でモデルが重複することを明記。
- 比較条件を独立した領域に集め、比較表は「モデル」「推論が実行される場所」「標準価格」「その他」の2段ヘッダで整理。
- スマートフォンでは検索を常時表示し、追加の絞り込みを開閉式にする。
- 全幅テーブル、行内詳細、リージョン行列、言語・テーマ切り替えは引き続き利用可能。

再生成: `npm run build` の後、`node docs/mockups/build-reference-v3.mjs`。
`reference-v2.css` / `reference-v2.js` を共通部分として利用し、`reference-v3.css` / `reference-v3.js` で案03の配置と集計を追加しています。本番画面は変更していません。

ブラウザで集計のフィルタ連動、国内限定時のGlobal除外、未取得時の件数、複数提供元選択、並べ替え、リージョン行列、日英切り替え、行内詳細、375px幅でのフィルタ操作と横はみ出しを確認しています。

### 案03：リクエスト図の更新

`reference-v3-flow.css` / `reference-v3-flow.js` で、推論先の図をネイビーの背景・シアンの発光ライン・デバイス型の送信元アイコンに変更。既存のSVGの座標・リージョン境界・矢印・出典は保持し、リクエストと応答の経路に装飾アニメーションを追加しています。図は通信経路の概念図で、実通信を表示するものではありません。

利用不可の推論方法と `prefers-reduced-motion: reduce` ではアニメーションを表示しません。日英切り替え、Globalの境界表現、ダークテーマ、375px幅での図内スクロール、SVGのID重複なしをブラウザで確認しました。

URLに `?q=Claude%20Haiku#flow` を付けると、対象モデルの詳細を開き、図へ移動して確認できます。

### 案03：推論先の地図

`reference-v3-map.js` / `reference-v3-map.css` で地図と通信経路図の切り替えを追加しました。Geoの地点・経路は `data/profiles.json` の起点別推論先から生成し、推論先ボタンで対応地点を強調できます。In-Regionは送信元だけを表示。Globalでは世界地図と送信元を表示し、固定された推論先を描きません。線は候補経路で、各リクエストが処理されるのは候補のいずれか1か所です。

地点は代表都市による概略位置で、AWS施設の所在地ではありません。陸地データは [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/) の public domain データ `ne_110m_land`。取得元は https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_110m_land.geojson 。`assets/ne_110m_land.geojson` をビルド時にHTMLへ埋め込み、表示時の外部通信は不要です。

ブラウザで東京・大阪のGeo、APACの6地点、地点選択、通信経路図への切り替え、Globalで推論先の点と経路がないこと、375px幅でページの横はみ出しがないことを確認しました。

### 地図と保存先を一体化

起点を地図領域の中央に固定し、シアンの矢印で「推論する場所」、アンバーの矢印で起点に残る「監査ログなどの保存先」を接続しました。矢印は地点と説明の対応を示します。呼び出しログは有効化時の情報であり、所在地が同一リージョン要件からの推定である点を図中に明示しています。狭い画面では図のみ横スクロールできます。

東京起点のGeo／Globalの中心座標、保存先表示、推論先選択、通信経路図への切り替え、375px幅でページ全体が横にはみ出さないことをブラウザで確認しました。

### 地図上で処理・保存先を表現

下部の説明カードとカードへの矢印を撤去。地図中央の送信元から、データにある各推論先へ直接矢印を描き、各地点に「推論」、送信元の隣に監査ログなどの保存先を表示します。近接する地点のラベルは重なりを避けて配置します。Globalでは固定推論先を推測して描きません。

`?q=Nova%20Lite#geo-map` でAPACのGeo地図を直接開けます。ブラウザで東京を中心とした5本の他リージョン向け矢印、選択時の強調、In-Region、提供なし、375px幅での横はみ出しがないことを確認しています。

### Globalの世界地図

Globalには送信元から世界各地へ広がる11本の装飾矢印と光のアニメーションを追加。終点は模式的な位置であり、実際の対応リージョン一覧や通信状況を表すものではないことを地図内に明示しています。監査ログなどの保存先は送信元に表示します。`?q=Claude%20Haiku#global-map` で直接開けます。

Globalへの直接リンク、11本の矢印、375px幅でのページ横はみ出しなし、reduced-motion時のアニメーション非表示をブラウザで確認しました。

### Geo / In-Regionのアニメーションとデータ所在の精査（2026-09-20）

Geoは実データの候補経路に入力の光と応答の戻り線を追加。In-Regionは中央の起点で完結する周回線を表示します。周回線は地理的なリージョン境界ではありません。`#local-map` でIn-Region、`#geo-map` でGeoを直接表示できます。

公式資料をContext7とAWSドキュメントで確認し、「推論だけが外に出て、すべての保存データは起点だけに残る」という断定を避けました。

- 推論の入力プロンプトと出力結果もリージョンをまたぎます。
- CloudTrailの記録元は送信元。GlobalのCloudWatch / CloudTrailも送信元での記録が明記されています。
- 呼び出しログは既定で無効。bedrock-runtimeで有効化したログの出力先は、設定と同じアカウント・リージョンのCloudWatch Logs / S3です。送信元保存はこの条件からの推定として区別しています。
- 一部モデルでは不正利用検知のため、推論先で入出力を保存する例外があります。In-Regionも保存なしを保証しません。
- 利用者が設定するログ転送や複製は図の対象外です。

参照: [Cross-Region](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)、[Geo](https://docs.aws.amazon.com/bedrock/latest/userguide/geographic-cross-region-inference.html)、[Global](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html)、[呼び出しログ](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html)、[不正利用検知](https://docs.aws.amazon.com/bedrock/latest/userguide/abuse-detection.html)。モックアップ内の図説明を修正し、出典リンクを追加。既存のsrcやデータは変更していません。

確認: Geoの5候補経路と光、選択時の強調、In-Regionの周回、提供なしではアニメーションなし、reduced-motionで光を非表示、375px幅でページ横はみ出しなし、JS構文チェック。

### 保存の例外注記をモデル別に限定

`data/model-policies.json` に例外対象の基盤モデルID、対象トラフィック、最大保存日数、
適用除外、出典、確認日を追加。モデルIDの完全一致で注記を表示する。
Nova / Haikuは非表示、Fable 5 / 5.1は全入出力、GPT-5.6 Sol / Terra / Lunaは
分類器で検知された入出力の保存を表示。未登録をZDR保証とは解釈しない。
APIスナップショットとは別の手動管理ファイルなので再取得で消えない。

ブラウザでNova / Haikuの非表示、Fable / Solの条件付き注記を確認。

### 地図の情報整理と起点内の推論経路

重複していた凡例・キャプション・データ説明カード・脚注を整理。地図上は地点と役割、上部は一行の凡例、下部は短い説明と開閉式の「説明・出典」に統合しました。モデル固有の保存例外は引き続き該当モデルだけに表示します。

Geoの起点が推論先一覧に含まれる場合にも起点内の周回矢印を描き、地点選択で強調できます。Globalの模式図から起点内の推論可否を推測しません。利用不可の方式では地図・SVG・アニメーション・表示切り替えを生成せず、利用不可の短い説明だけを表示します。

ブラウザで国内Geoの東京周回＋大阪向け矢印、東京選択の強調、説明の開閉、通信経路図切り替え、提供なしの地図非表示、対象モデルの保存注記維持、375px幅でページ横はみ出しなしを確認しました。

### 地図表示に一本化

案03の「地図・処理と保存先 / リクエスト・応答」切り替えを撤去し、地図のみを表示します。
旧通信経路図のDOMも置き換え、重複したキャプションを残しません。従来の図専用CSS・装飾JSは
案03のビルド対象から外し、レビュー用URLの処理を地図JSへ移しました。過去の図用ファイルは履歴として残しています。
地図内の入出力の凡例、起点でのログ記録、モデル別の例外、開閉式の説明・出典は維持します。

ブラウザで旧図・切り替えがないこと、Geoの起点内推論と選択、Globalの矢印、In-Region、
提供なし表示、説明・出典の開閉、375px幅でページ横はみ出しなしを確認しました。

### 地図の余白・縮尺

起点を中心に経路と地名の描画範囲から上下の余白を対称に切り詰めます。地図の縮小ではなく表示範囲の調整なので、文字や地点の大きさは維持します。見出しの重複する英語ラベルも省きました。
Geoは近距離の推論先をより大きく表示する初期縮尺に変更。右上の「− / 全体 / ＋」で起点を中心に1〜2.5倍へ拡大でき、全体で初期表示に戻せます。拡大時に表示領域の高さは変えません。
国内Geo・APAC・Global・In-Regionの中心と経路の収まり、拡大とリセット、375px幅でのページ横はみ出しなしをブラウザで確認しました。

### 新しいモデル順

表の直前の「並び順」に「新しい順」を追加。`releasedAt`（Bedrock提供開始日時）の降順で、
提供元の優先指定は適用しません。日付不明は末尾、同日時は提供元・モデル名・ID順で安定させます。
`?sort=newest` で共有・復元でき、リージョン行列にも選択した並び順を引き継ぎます。
モデル名のツールチップには提供開始日を表示します。データの正規化と並べ替え機能はsrc側に実装し、
モックアップにもビルドで反映しています（デザイン案全体の本番採用・デプロイは未実施）。

案03の承認後、配置・地図・スタイルを `src/scripts/presentation.js`、
